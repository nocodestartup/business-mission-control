Mapa do ecossistema

Recursos diferentes resolvem problemas diferentes.

Os nomes podem aparecer juntos na interface, mas não são sinônimos. Use a função principal para decidir.

Skill

Ensina um fluxo.

Instruções, critérios e recursos para um trabalho repetível.

Use quando o método se repete.Entender skills ↗
Plugin

Empacota capacidades.

Pode reunir skills, conexão MCP e outros recursos instaláveis.

Use quando uma solução pronta atende o caso.Entender plugins ↗
MCP

Conecta ferramentas e dados.

Expõe operações estruturadas para acessar um sistema externo.

Use quando a tarefa precisa de informação viva ou ação controlada.Entender MCP ↗
Subagente

Divide trabalho independente.

Executa uma parte com contexto próprio e devolve resultado ao agente principal.

Use quando as partes podem avançar em paralelo.Entender subagentes ↗
Tarefa longa

Persegue um objetivo.

Mantém continuidade por várias etapas e verificações.

Use quando o resultado é único, mas demorado.Entender tarefas longas ↗
Automação

Executa depois ou repete.

Agenda um trabalho com entrada, frequência e saída definidas.

Use quando o momento é parte do requisito.Entender automações ↗

A arquitetura atual de plugins separa skills e MCP e recomenda começar pela menor forma capaz de atender o caso: documentação oficial da OpenAI.

Roteador de necessidade

Escolha pelo verbo do problema.

Selecione a necessidade dominante. A recomendação é um ponto de partida; disponibilidade, conta, permissões e impacto ainda precisam ser conferidos.

Ver o mapa sem interação
  • Repetir método: skill.
  • Conectar serviço: plugin existente ou MCP controlado.
  • Dividir partes independentes: subagentes.
  • Objetivo único e longo: tarefa longa com checkpoints.
  • Executar depois ou repetir: automação.

Aplicação no case

Para o próximo passo, a skill já basta.

O M7 precisa de um handoff preciso, não de dados externos, recorrência ou trabalho paralelo. Adicionar outra integração só aumentaria superfície de risco.

  • NecessidadeLevar estado revisado do M5 e critérios para uma conversa independente de validação.
  • EscolhaSkill handoff da Lume para atualizar diretamente o HANDOFF.md do projeto.
  • ForaPlugin, MCP, subagente e automação não são necessários para essa transição.
  • GateRevisar o mapa antes da invocação e conferir o diff depois; a skill não amplia autorização para corrigir ou publicar.
Pedido para revisar a expansão
Continue nesta mesma conversa. Para cada necessidade que identifiquei, compare skill, plugin, MCP, subagente, tarefa longa e automação pelo menor recurso suficiente.

Mostre: necessidade concreta; recurso recomendado; por que opções menores não resolvem; acesso ou permissão adicional; risco; forma de revisar; e condição para interromper. Não instale, conecte, agende nem execute nenhum recurso novo.

Para a transição ao M7, confirme se a skill handoff já vinculada é suficiente. Se for, preserve as demais expansões apenas como mapa futuro e aguarde minha revisão.

Você também pode selecionar e copiar o texto manualmente.
